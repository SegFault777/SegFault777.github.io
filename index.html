MINIWIN

A tiny 32-bit x86 desktop operating system that boots from a single MBR disk image into a Windows-95-flavored GUI. Built from the ground up without libc, a bootloader framework, or borrowed kernel code.

01 / THE PROJECT

A small OS project, built close to the metal.

MiniWin is a dependency-free 32-bit x86 OS. Its bootloader handles the real-mode setup and protected-mode jump; the kernel then runs its own display, input, storage, desktop, clock and application code.

02 / WHAT'S INSIDE

What is actually in the repository.

The README describes a working set of low-level components and a small desktop environment; the project is still being built out.

BOOT

512-byte MBR loader

Sets a real VBE mode, switches from real mode to protected mode, and loads the kernel with BIOS INT 13h extended LBA reads.

KERNEL

Freestanding C

Includes VGA, PS/2 keyboard and mouse, PC speaker, ATA storage, PCI enumeration and COM1 serial logging, all without libc.

DESKTOP

Classic window manager

Drag, resize, minimize and maximize windows. Clicking a window brings it to the front, while the taskbar keeps minimized windows.

APPS

Notepad + Settings

Notepad supports multiple documents and real persistent saves. Settings switches the system language and controls input methods.

IME

Hangul IME

A 2-beolsik-style jamo composition system backed by all 11,172 modern Hangul syllable glyphs.

CLOCK

Real CMOS time

The taskbar clock reads the hardware RTC and can show English or Korean date and time formats.

LANGUAGES

English / 한국어

MiniWin currently supports two system UI languages: English and Korean. Settings can switch the language live, and the Korean option includes the built-in Hangul IME.

03 / BUILD & RUN

Make the disk image.

Build on Linux with NASM, a 32-bit-capable GCC, and ld. On Debian or Ubuntu 64-bit hosts, gcc-multilib may be needed.

QUICK START — SHELL
# clone the repository
$ git clone https://github.com/SegFault777/MiniWin.git
$ cd MiniWin

# build → build/os-image.img
$ ./build.sh

# boot it in QEMU
$ qemu-system-i386 -drive file=build/os-image.img,format=raw

MiniWin is running.
Current state: RTL8139 and e1000 drivers have been verified for ARP traffic in QEMU, but MiniWin does not yet have an ARP/IP/TCP stack or browser. File Manager and dynamic program loading are also not implemented.
04 / NETWORKING

Two real NIC drivers. Still a work in progress.

The README documents two independently verified network-card drivers. They can exchange a real ARP request/reply with QEMU's SLIRP gateway, but MiniWin does not have a full network stack yet.

RTL8139

Port-I/O driver

Includes a ring-buffer RX path and four-slot round-robin TX. The README records an end-to-end ARP reply received from QEMU's gateway.

e1000 / 82540EM

MMIO + descriptor rings

Uses memory-mapped registers plus RX/TX descriptor rings. It is exercised without paging, so physical addresses can be used directly for the card's MMIO and DMA buffers.

LIMIT

Driver layer, for now

Both drivers are polled rather than interrupt-driven. Above them there is no ARP/IP/TCP stack, DNS, TLS, or browser yet.

MiniWin Canary

Canary 버전에서 달라진 점

Canary는 일반 MiniWin을 바탕으로 네트워크 스택 작업을 쌓아 올린 개발 버전입니다.

추가된 헤더: arp.h, dhcp.h, ip.h, net_stack.h

현재 TCP는 지원하지 않습니다. Canary의 핵심 변화는 네트워크 스택 관련 코드가 추가된 것입니다.

이미지 파일은 일반 버전의 약 600 KB에서 Canary에서는 약 256 KB로 줄였습니다.
